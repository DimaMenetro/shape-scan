Updated Claims
C1 [Established] The 256×256 Markov transition matrix maps natively to a toroidal
topology because byte values are cyclic (0-255 wraps). The parametric torus form r(u,v)
= r_base + k · P(v|u)^γ  provides a mathematically faithful representation with no edge
discontinuities and no projection distortion.
C2 [Established] The Gielis superformula in its 3D spherical-product form produces closed
parametric surfaces governed by a small set of coefficients spanning regular polyhedra
through organic blobs to highly asymmetric stellated forms.
C3 [Established] Compression ratio ( compressed_size / original_size  via DEFLATE) is a
structurally distinct measurement from Shannon entropy. Together they distinguish
encrypted blobs from polymorphic obfuscation attempting to mimic encryption.
C4 [Experimental — falsifiability defined] The superformula coefficient bindings ( m , n₁ ,
n₂ , n₃ , a , b ) chosen in this plan will produce visually distinguishable morphologies
across major file classes. Falsifiability test: scan a curated set of six file classes; if three or
more render as visually indistinguishable mugshots, the binding scheme has failed and must
be re-tuned. Fallback: the torus fingerprint view remains fully functional and provides
scientifically defensible Markov representation regardless of mugshot binding outcome.
C5 [Established] Spectral graph layout via Laplacian eigenvectors produces edge-energy-
minimizing embeddings. JavaScript power iteration handles graphs up to ~512 nodes within
real-time budget; force-directed fallback above this threshold.
C6 [Experimental — falsifiability defined] The hybrid Markov projection for the
superformula view (equatorial band + polar cap tessellation) will preserve byte-transition
distinctiveness without visible seam artifacts. Falsifiability test: if the band-cap transition
creates a visible discontinuity that overrides the morphological signature, smoothing kernels
must be applied or the projection scheme abandoned. Fallback: torus fingerprint view is
unaffected — Markov data renders losslessly there.
C7 [Established] SQLite via rusqlite preserves the Semantic Firewall. Numeric TEMReport
fields, SHA-256 prefix, and timestamps only.
C8 [Established] The AISE intent score maps to mesh shading parameters via dihedral
crease angle threshold θ_crease = π · (1 - I_AISE) . Applied uniformly to both
fingerprint and mugshot views.
C9 [Established] The dual-render UI pattern (primary viewport + auto-rotating thumbnail
with click-to-swap) is implementable using two independent Three.js scenes with shared
TEM data input. Total vertex budget ~32K (16K per render) is well within WebGL real-time
capacity. Independent auto-rotation on the thumbnail is a single rotation matrix update per
frame, negligible compute cost.

shapes emerge from telemetry, not from aesthetic choice. The torus view’s curvature comes

operator’s pattern-recognition layer cross-references the two representations over time,
building dual-channel intuition for file morphology. This is operator-amplification behavior —
the visualization does analytical work inside the operator’s head, not just on the screen.

 Critical — operator interface

2C.1: Layout Composition
Primary viewport: large central display area, full interactive controls bound via
controls.js . Default occupant: superformula (mugshot).
Thumbnail viewport: smaller display area positioned in elegant front-and-center
proximity to the primary (specific positioning determined during UI implementation —
candidates include corner inset, side-by-side with size differential, or floating overlay).
Default occupant: torus (fingerprint).
Both viewports always visible. No mode-switching, no menu navigation, no toggling.
2C.2: Swap Behavior
Trigger: Click or tap on the thumbnail viewport.
Action: Positions swap. Primary becomes thumbnail, thumbnail becomes primary.
Controls re-bind to new primary.
Transition: Brief animated swap (~300ms) for visual continuity. Liquid Glass aesthetic —
smooth, low-noise.
Reverse: Click or tap on the new thumbnail (which was previously the primary) swaps
positions back.
State persistence: Current primary/thumbnail assignment is session-local — does not
persist across application restarts. Default state restored on app launch.
2C.3: Independent Thumbnail Auto-Rotation
Behavior: The thumbnail viewport (whichever render currently occupies it) rotates
continuously and slowly around its central vertical axis. Rotation runs independently —
does not pause, sync, or react to operator interaction with the primary viewport.
Rotation rate: ~6 RPM (one full rotation per 10 seconds). Slow enough to read as
ambient motion, fast enough to display the full 3D form within reasonable observation
time.
Implementation: Single rotation matrix update per frame in the thumbnail’s animation
loop. Negligible compute cost.
Constraint: Thumbnail is never manipulable. No input handlers attached. Auto-rotation
is the only motion. This is a hard constraint — the swap-trigger click handler is the only
event the thumbnail responds to.
2C.4: Doctrinal Note — Fingerprint-Mugshot Pattern
The dual-render layout formalizes a new architectural precedent for Project Opus, named
the Fingerprint-Mugshot Pattern:
When a single visualization layer faces tension between mathematical fidelity
([Established] math) and operator-facing categorical distinctiveness (Tesla-Principle-
authorized [Experimental] math), the resolution is to render both representations
simultaneously in a primary/thumbnail composition with click-to-swap. The two views are
not competitors — they serve distinct operational functions and produce dual-channel
pattern recognition in the operator over time.
This pattern is generalizable beyond the Markov visualization context. Future Project Opus
instruments facing similar tensions should consider this template.
